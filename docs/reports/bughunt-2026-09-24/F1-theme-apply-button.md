# F1. Themes show on the preview first, Apply puts them on the whole app
**Status:** done (owner's request: "when you select themes the theme should first appear on the little preview screen and once you click APPLY then it applies on the actual full site").

**What you'd notice:** in Settings > Appearance, picking a preset, one of your themes or a shared theme, and changing colours, now change only the small preview. The rest of the app, the page around the preview included, stays on the theme you use. A bar above the tabs says what the preview shows ("Midnight shows in the preview only.") with **Apply** and **Back to current**. Apply makes it your theme everywhere and saves it; Back to current puts the preview back. With nothing to apply the same bar says "In use: Ember." In the Themes list, the one the preview shows is outlined and the one you use has an "In use" tag.

**Before:** every pick applied to the whole app and saved at once; colour edits recoloured the whole app live and saved themselves 0.6 s later (a preset edit made "My Midnight" on the first change).

**What changed:**
- The store's `preview` (painted on the whole app) is now `draft` (`{ target, edit }`), which only the page's preview pane shows. `ThemeApplier` paints the active theme alone, so `notifyShell` (Android bars, desktop window) fires only on Apply.
- `useThemeEditor` keeps the draft in the store and has `apply` and `discard`. Apply picks the right save: a preset or saved theme as it is is selected (`PATCH /api/theme`); edits to one of mine save its colours (`PATCH /api/themes/:id`) and then select it (or adopt the server's `active` when it was already in use); edits to a preset or a kept copy create "My <preset>" (`POST /api/themes`) and select it. Nothing is created before Apply.
- An unreadable pair turns Apply off with the same line as before ("Not saved: accent links on the background is hard to read."); Fix it changes the draft and turns Apply back on.
- Leaving the page applies and saves nothing: the N1 flush on unmount and on pagehide is gone. The draft stays in memory for the session, so coming back shows it again with Apply. N1's tests and report note are updated to match (owner's request).
- N2: every apply and delete runs through one queue, so an apply that saves colours then selects always lands before a later switch. The server lock is unchanged. V10, the cap of 20, the Share tab and first paint from the cookie are unchanged.
- New saves a copy of what the preview shows to My themes and shows it in the preview; Apply puts it in use. Rename, duplicate, delete and sharing still act at once (they change the list, not the theme in use).
- The bar keeps one height with or without buttons, so a first pick does not push the preset list down under the pointer. It sticks to the top of the page while there is something to apply (checked at 390 on a scrolled Colours tab).
- Docs: `docs/themes.md` sections 3, 4, 5, 7 and 8, and the 0.7.0 changelog bullet ("Whatever you pick or change shows on the small preview first; press Apply to use it on the whole app, or Back to current to leave things as they were.").
