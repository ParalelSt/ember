# X11. PocketBase could refuse to start after an admin-UI edit
**Status:** fixed.
**What you'd notice:** the app going down and staying down: PocketBase would exit right after boot with nothing playing and no obvious reason, if anyone had ever opened a collection in the admin UI (`/_/`) and saved it, even without changing anything visible.
**Why it happened:** the tabs setup hook checks its indexes on every boot by comparing the exact index text. Saving a collection from the admin UI rewrites that text (quoting the column names a little differently) even when nothing meaningful changed, so the hook thought an index had gone missing and tried to create it again. PocketBase refused (an index with that name already existed) and the hook's crash took the whole server down with it, before it ever started serving.
**What changed:** the hook now compares indexes by their name, not their exact text, so a harmless re-save is recognised as "already there." As a safety net, every setup hook's collection save is now wrapped so a save that still fails only logs a warning and lets PocketBase keep booting, the way the superuser setup already worked. Files: `pocketbase/pb_hooks/ensure_tabs.pb.js`, and the same save-safety wrap in `ensure_changelog_fields.pb.js`, `ensure_privacy_fields.pb.js`, `ensure_plugin_settings.pb.js`, `ensure_themes.pb.js`, `ensure_uploads_artwork.pb.js`, `ensure_track_availability.pb.js`, `ensure_tracks_rules.pb.js`, `ensure_likes_fields.pb.js`, `ensure_uploads.pb.js`, `ensure_imports.pb.js`, `ensure_sessions.pb.js`.
**Compare:** before = `c023593`, after = `20ffa04`.
- Test: `PB_BIN=/path/to/pocketbase node tests/pb-hooks-tabs-index-repair.test.mjs` (a throwaway PocketBase, this checkout's hooks, a temp data dir).
  - Before: `FAIL boot 2 still starts after the admin UI touched the indexes  (... GoError: indexes: (3: Failed to create index idx_tabs_song_key - SQL logic error: index idx_tabs_song_key already exists ...)`, `FAIL boot 2 did not crash on a duplicate index`, 2/4 passed.
  - After: `PASS boot 1 starts (tabs collection created)`, `PASS the tabs indexes were re-saved with normalized SQL`, `PASS boot 2 still starts after the admin UI touched the indexes`, `PASS boot 2 did not crash on a duplicate index`, 4/4 passed.
- Try it yourself: on the sandbox, open `/_/` (admin UI), click into the `tabs` collection, and Save without changing anything, then restart PocketBase. It comes back up either way now.
**Risk:** low. Only touches setup hooks that run once per boot; no user-facing behaviour changes.
