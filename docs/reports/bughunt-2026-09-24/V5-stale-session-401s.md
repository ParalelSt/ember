# V5. A dead session on the sign-in page fired a burst of failing calls and bug reports
**Status:** fixed (regression from W05).
**What you'd notice:** coming back with a session the server no longer accepts (revoked, or after a reinstall), the sign-in page quietly made about ten calls that all failed, filled the console with errors and sent up to 3 automatic bug reports. /privacy and /terms bounced you to sign in. After signing out, the song left in the player kept asking for lyrics.
**Why it happened:** the sign-in gate saw the session was dead but left the cookie in place, so the page was still drawn as if you were signed in and everything signed-in started loading. Each failure was logged as an error, which is what sends a bug report. The lyrics lookup ran for any loaded song, signed in or not.
**What changed:** the gate now deletes a refused cookie and keeps it from that page load; if PocketBase is simply down it answers "try again" (503) instead of "signed out", so an outage never costs anyone their session. Any "not signed in" answer from our API now clears the app's session at once (so the rest stops), is logged as a warning, and never sends a report; nothing reports from /auth; public pages are never bounced. Nobody counts as signed in on /auth, and lyrics and the song-availability check only run signed in.
