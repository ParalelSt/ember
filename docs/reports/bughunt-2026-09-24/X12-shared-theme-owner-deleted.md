# X12. Deleting a member and their shared themes
**Status:** not fixed (not a bug: the existing protection already covers it).
**What you'd notice:** nothing, for anyone already using the theme. Deleting the member who shared it does remove that theme from the "Shared by others" list for people who haven't picked it yet, exactly as if that person had deleted or unshared it themselves.
**Why it looks like a bug:** `themes.owner` is set to delete its rows along with the member (so an orphaned row, owned by nobody, never lingers). That does remove every theme they had shared. It reads like "other people using it lose it."
**Why it isn't:** Ember never keeps someone's active theme as a live pointer to the shared row; picking a theme copies its colours onto the person's own account straight away (`docs/themes.md`, section 4). `GET /api/theme` (`apps/web/app/api/theme/route.ts`) checks on every load whether the theme it's linked to still exists and is still visible; if not, it drops the link and keeps the colours exactly in place, "so nobody's look breaks under them." That check doesn't care why the row is gone: the owner deleting their own theme, unsharing it, and a member's account being deleted (which deletes their themes the same way) all land on the exact same "row is gone" path, already covered by two existing tests plus a new one for this exact scenario.
**What changed:** nothing in the app. Added `apps/web/app/api/themes/themes-routes.test.ts` ("keeps a copy of a shared theme even when its owner vanishes"), which deletes the row the way PocketBase's cascade does (not through the app's own delete route) and confirms the person using it keeps their colours, with the dead link dropped.
- Test: `cd apps/web && npx vitest run app/api/themes/themes-routes.test.ts`: 18/18 pass, including the new case.
- Try it yourself: on the sandbox, share a theme from one account, apply it from a second account, then delete the first account in Admin > Users. The second account's colours are unchanged after its next page load; the theme is gone from Settings > Appearance > Share for anyone who hadn't picked it up yet.
**Risk:** none (no code change). If the owner-name-on-a-still-usable-row case ever comes up (it doesn't today, since the row itself never survives its owner), the fix would be making `owner` optional and cascade off, showing "by a former member".
